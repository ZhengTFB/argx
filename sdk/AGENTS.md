# ARGX 集成规范（写给 AI 编码助手）

你在帮人做一个 ARG（替代现实游戏）网页。这份文件告诉你怎样让**玩家房间里的灯、蜂鸣器、振动马达**跟着剧情动。
读完就能动手，不需要看别的文档。

---

## 1. 三十秒接入

复制这三段，放进作品的 HTML：

```html
<!-- 1. 引入 SDK（和作品放在同一个目录，或者改成你的路径） -->
<script src="argx.js"></script>

<!-- 2. 给用户一个连接装置的按钮（浏览器要求首次连接必须由真实点击触发） -->
<button onclick="ARGX.connect()">连接装置</button>

<script>
  // 3. 初始化。不传参数最省事：能连真装置就真装置，连不了就静默降级
  ARGX.init();

  // 4. 剧情走到关键点，触发一个事件
  ARGX.fire('reveal');
</script>
```

**验证埋点生效**：打开浏览器 DevTools 的 console，没有装置时会看到这样的行——

```
[ARGX] batch: light.main {"i":1,"ramp":120,...} + sound.beeper {"i":1,"dur":250,...}
```

**看到这行就等于埋点接对了。** 没有这行，事件名多半拼错了。

## 2. 事件词表

`fire()` 的字符串用下面这几个词。**不要自己发明词**——硬件端的清单会因此变成垃圾场，而且你已经有一条
人话的通道了：词表把这些词翻译成"哪路灯、多亮、多久"。

| 事件 | 用在什么地方 | 会动什么 |
|---|---|---|
| `calm` | 平静、安全、缓和的段落 | 灯慢慢亮回来一点 |
| `tension` | 有东西不对劲、气氛收紧 | 灯缓缓压暗 |
| `reveal` | 解答揭晓、谜题解开 | 灯猛地一亮 + 一声短响 |
| `danger` | 惊吓点、威胁逼近 | 灯急闪 + 蜂鸣 + 振动 |
| `relief` | 脱险、松一口气 | 灯柔和回暖 |
| `ending` | 通关、故事收束 | 灯常亮不灭 + 一声长鸣 |

优先级已经配好了，你不需要传任何参数。

## 3. 埋点规则

**一个场景保留 3–8 个 cue。** 这是硬指标，写完数一数：

```
grep -c "ARGX.fire" 你的文件.html
```

（剧情若是数据驱动的——比如剧本写在一个 JSON 里——数那份数据里的 cue 条数，一样。）

**只在情绪转折点触发。** 判断标准是这一句：**这一刻玩家的心跳有没有变化？**
有，就埋；只是"又点了一下"，就不埋。

该埋的位置：

- 解开一个谜题 → `reveal`
- 发现一条关键线索 → `tension`
- 进入新场景、场景切换 → `calm`
- 出现威胁、突发惊吓 → `danger`
- 走到分支的某一端、结局 → `relief` / `ending`

不该埋的位置：每次鼠标点击、每次翻页、每个按钮、每次输入错误。
**灯一直在闪等于没闪**——真到了要埋的那一刻，玩家已经麻木了。

## 4. 硬件不是判定源

装置只负责"演"。**剧情判定一行都不许依赖它。**

```js
// 对：不管有没有装置，门都开，剧情都往下走
function onPuzzleSolved() {
  showNextScene();      // 先推进剧情
  ARGX.fire('reveal');  // 再让房间动一下，失败了也无所谓
}

// 错：等装置的回应才决定剧情 —— 没买装置的玩家会永远卡在这里
ARGX.on('ack', () => showNextScene());
```

**没买装置、没插线、浏览器不支持的玩家，必须能完整通关。** 这是硬性要求，不是优化项。

## 5. 要更细的控制

| 你要的效果 | 怎么写 |
|---|---|
| 精确亮度 / 时长 / 渐变 | `ARGX.cue('light.main', { i: 0.4, ramp: 2000, dur: 5000 })` |
| 灯和声音**同时**起 | `ARGX.batch([{id:'light.main',p:{i:1}}, {id:'sound.beeper',p:{i:1,dur:400}}])` |
| 灯一直亮着不灭 | `ARGX.cue('light.main', { i: 0.9, hold: true })` |
| 全部熄灭、回到待机 | `ARGX.reset()` |
| 确认装置真的收到了 | `const st = await ARGX.state()`（没人应答给 `null`） |
| 玩家碰了物理开关 | `ARGX.on('input', (id, f) => ...)` |

参数只有五个：`i` 强度 0~1、`dur` 持续毫秒（缺省 30 秒）、`ramp` 渐变毫秒、`pri` 优先级 0~3、`hold` 常驻。
**只发语义（`light.main`），永远不要发引脚电平（`GPIO4 HIGH`）**——哪个引脚挂了什么由装置端决定。

## 6. 完成后的自检清单

逐条验一遍，每条都能自己动手确认：

- [ ] 页面在 `https://` 或 `http://localhost` 下打开（看一眼地址栏）
- [ ] 本地测试用的是本地服务器，不是双击文件（`file://` 下浏览器禁用串口）
- [ ] 没有装置时页面不报错、不弹窗，DevTools console 里能看到 `[ARGX]` 开头的 cue 行
- [ ] 连接装置由一个按钮的真实点击触发，页面加载时**不**自动连
- [ ] 触发点的总数在 3 到 8 之间（`grep -c "ARGX.fire"`，或者数剧本数据里的 cue）
- [ ] 每个埋点都能说清"这一刻玩家心跳为什么变化"
- [ ] 事件名全部来自第 2 节的词表
- [ ] 拔掉装置重玩一遍，剧情从头走到尾，一次都没卡住
- [ ] `ARGX.hint()` 非空时，页面上把它显示出来了（它会告诉你当前环境缺什么、下一步做什么）

## 7. 三种运行状态

| 状态 | 什么时候是这种 | 表现 |
|---|---|---|
| 真装置 | 用户点了连接按钮并选了串口 | 房间真的动 |
| 模拟模式 | 没插装置、浏览器不支持、或者用户还没连 | cue 打进 console，剧情照常 |
| 宿主通道 | 作品被别的页面嵌着跑（宿主给了现成通道） | 跟着宿主的连接走 |

三种状态对作品代码**没有任何区别**——这是故意的。

## 8. 常见错误

| 症状 | 原因 |
|---|---|
| DevTools 里没有 `[ARGX]` 行 | 事件名拼错了（对照第 2 节），或 `ARGX.init()` 没调用 |
| 点了连接按钮但浏览器不弹端口选择框 | `ARGX.connect()` 不在用户点击的调用栈里（例如包在 `setTimeout` 里） |
| 页面上写着 `file://` 的警告 | 双击打开的。跑 `npx serve` 或 `python -m http.server 8000` |
| 手机上装置不动 | Web Serial 只有桌面 Chrome / Edge 有。手机能玩剧情，装置不会动 |
| 亮的比预期少 | 装置缺那一路能力，SDK 自动跳过了。这是正常行为，不是 bug |

需要自己加事件、接自己做的硬件，看 `README.md` 与 `../protocol/PROTOCOL.md`。
