## 浏览器要求

| 要求 | 说明 |
|---|---|
| 浏览器 | 桌面版 Chrome 或 Edge（116 以上）。Firefox、Safari 都不支持 Web Serial |
| 地址 | 必须是 localhost 或 HTTPS。用 file:// 直接打开页面时串口会被浏览器禁用 |
| 设备 | 桌面电脑。手机端浏览器不支持，这是浏览器的限制，不是这一版没做 |
| 操作 | 第一次连接必须由你**亲手点一次**按钮，浏览器只允许在真实的点击里弹端口框 |

> [!NOTE]
> 最后一条常被当成"这个按钮有时候不灵"。它是浏览器的安全设计：网页不能自行枚举串口设备。连接动作必须从按钮点进去，中间不能插等待。

## 两个 USB 口的区别

| 口 | 丝印 | 能不能用 | 说明 |
|---|---|---|---|
| 原生 USB | USB | ✅ 用这个 | 芯片自带的 USB 控制器，控制台靠它通信 |
| USB-UART 桥 | UART / COM | ❌ 只供电 | 板上那颗转换芯片，供电正常但控制台连不上 |

> [!WARNING]
> 如果你是在 Arduino IDE 里刷固件，要用原生 USB 口时必须在 IDE 里把 USB CDC On Boot 设成 Enabled，否则串口是哑的：板子看着在跑，但一个字都不往外发。

## 为什么没有"扫描设备"这一步

浏览器没有提供这个能力。Web Serial 只有两个入口：`requestPort()` 弹出由操作系统绘制的端口选择框，网页读不到列表内容；`getPorts()` 只返回此前授权过的端口。因此"扫描到两台设备、每行一个连接按钮"的界面无法实现。

## 连上了会怎样

- 顶部徽标从「未连接」变成「已连接」
- 设备页出现设备 ID（形如 ARGX-0001）和它自报的能力清单
- 右侧状态栏开始每 3 秒收到一次心跳，栏底显示往返毫秒数
- 调试页的时间线开始出现收发的帧

> [!DANGER]
> 如果 10 秒收不到装置的任何应答，会话层判定掉线：状态栏四路回到待机、顶部徽标退化、右下角弹一条通知。掉线属于设计内的降级，故事不会因此中断。
