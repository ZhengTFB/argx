## 最小接入示例

```html
// [head]
<!doctype html>
<meta charset="utf-8">
<script src="argx.js"></script>
<script>
  // 1. 初始化。没连装置、没有硬件、file:// 打开 —— 都静默降级，不抛错
  ARGX.init();

  // 2. 在剧情节点上发一个事件。作者只写事件名，不写能力 id 和参数
  document.querySelector('#reveal')?.addEventListener('click', () => {
    ARGX.fire('reveal');
  });
</script>
```

上面就是全部接入代码。`ARGX.init()` 自己找装置：在控制台里以 iframe 运行时用宿主通道，独立打开时找串口，两者都没有则往 console 打一行日志。

## 作者只写事件名

不需要知道哪一盏灯配多亮，也不需要知道优先级会不会被抢占。事件词表配在 SDK 里，作者只写这一刻发生了什么。内置六个：

| 事件 | 用在什么时候 | 它做了什么 |
|---|---|---|
| calm | 安定下来 | 灯光缓慢降到 25%，氛围优先级 |
| tension | 不对劲了 | 灯光 1.5 秒暗下去，氛围优先级 |
| reveal | 真相揭开 | 灯光快速打到满 + 一声短响，高优先级 |
| danger | 危险逼近 | 灯闪 + 长鸣 + 振动，高优先级 |
| relief | 松一口气 | 灯光柔和回到 50% |
| ending | 结局 | 灯光常驻 90%，不再自动熄灭 |

## 自己定义事件

```js
// 你的作品想要一个自己的组合
ARGX.defineEvent('door_lock', [
  { id: 'env.relay', p: { i: 1 } },
  { id: 'sound.beeper', p: { i: 0.8, dur: 120 } }
], { label: '门锁落下', desc: '继电器吸合 + 一声闷响' });

// 之后就像内置事件一样用
ARGX.fire('door_lock');
```

> [!NOTE]
> `fire()` 会按装置**实际声明**的能力过滤再发。"灯 + 蜂鸣 + 振动"这样的事件在只有灯的装置上不会整条丢掉，只演灯那一部分。协议里 `batch` 的校验是原子的，一条不合法整批都会被拒，所以这个过滤是必需的。

## 状态回查

```js
// 想知道装置现在什么样，去问它
const st = await ARGX.state({ timeout: 900 });
if (!st) {
  // 没人应答：装置没连、或者这一帧丢了。
  // 这**不是错误**，你的剧情该照常往下走
  return;
}
console.log(st.out['light.main']); // { i: 0.8, pri: 2, ttl: 2400 }
```

> [!DANGER]
> 剧情判定不得依赖装置。装置只负责演出，玩家答对答错永远由网页决定。装置没插、线掉了、端口框被取消，故事都必须照常玩下去。

## 埋点要克制

- 只在**情绪转折点**触发，一段文字里不要连发三次
- 一个作品保留 3–8 个触发点，超出这个数量会显得嘈杂
- 把事件挂在**"玩家做成了什么"**的那一幕上。挂在标题页会让玩家一进这一幕就看到灯闪，而他还没做任何事
- 不确定要不要加的时候，不加
