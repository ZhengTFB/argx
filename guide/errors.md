## 五个码

| code | 什么时候出现 | 怎么办 |
|---|---|---|
| bad_frame | 行以 { 开头但 JSON 坏了、缺必填字段、超过 512 字节、batch 为空或超过 8 条 | 检查 JSON 是不是被截断了。串口上这种多半是发太快 |
| unknown_cmd | c 字段不是已知命令 | 拼错了。注意大小写 |
| unknown_id | cue 里的 id 没注册过。整批 batch 会因此被拒 | 向装置要一次 caps，或者用控制台设备页的能力列表核对 |
| unknown_input | 注入的 input id 不在 caps.in 里 | 真机固件没有注册任何输入，所以这一条很常见 —— 见下 |
| bad_version | v 字段和装置的不兼容 | 协议版本不一致，换一份匹配的实现 |

> [!NOTE]
> 收到 unknown_input 说明**帧到了装置、装置也回了话**，上行链路是通的。

## err 帧的结构

```json
{"v":1,"c":"err","code":"unknown_id","seq":12,
 "msg":"没有注册过这个能力"}
```

err 里**没有 id 字段**：出错的 id 不会回传，只能靠 msg 和 seq 对应。这是当前实现的一处缺口。

## 不产生 err 的情况

- 不以 { 开头的行：静默丢弃，避免刷屏
- 参数超出范围：直接钳住。i 超出 0~1 钳到边界，dur 超过 30000 钳到 30000
- 没连装置、file:// 打开、连接失败：上层一律静默降级
