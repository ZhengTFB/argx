## 五个参数

| 参数 | 类型 | 缺省 | 含义 |
|---|---|---|---|
| i | 0 ~ 1 小数 | 1.0 | 强度。超出范围会被钳住，不会报错 |
| dur | 毫秒整数 | 30000 | 持续多久。上限 30000 |
| ramp | 毫秒整数 | 0 | 渐入多久。超过 dur 会被钳到 dur |
| pri | 0 ~ 3 整数 | 2 | 优先级，**数字越小越强** |
| hold | true / false | false | 常驻：忽略 dur，直到被抢占或复位 |

```json
// [head]
{"v":1,"c":"cue","id":"light.main","seq":12,
 "p":{"i":0.8,"dur":3000,"ramp":800,"pri":2}}
```

## 连续量与开关量

四路里有三路是**连续量**：灯、声音、振动；一路是**开关量**：继电器。两者的差异如下：

| | 灯 / 声音 / 振动 | 继电器 |
|---|---|---|
| 强度 | 有，0~1 连续可调 | 只看 i ≥ 0.5 算吸合 |
| 渐变 ramp | 有意义 | 无意义，物理上就是吸合与断开 |
| 界面上 | 滑杆 + 时长 | 一个开关，没有滑杆 |
| 切换动效 | 有过渡（260ms） | 硬切（0ms） |

> [!WARNING]
> 声音这一路，当前固件的强度是二值的：i > 0.02 输出 2.7kHz 方波，否则静音。虚拟装置按 i 做渐变，所以模拟器里能看到强度差异，真机上只有有声与静音两种状态。协议侧 i 仍是 0~1 的连续值，换成带 DAC 的驱动即可生效，协议不需要改。

## 优先级：谁抢谁

| 值 | 名字 | 典型用途 |
|---|---|---|
| 0 | critical | 复位、看门狗。永远抢占，并且先清空全部输出 |
| 1 | high | 剧情关键节点：揭示、危险 |
| 2 | normal | 默认值 |
| 3 | ambient | 氛围底色，随时可以被抢 |

规则只有一条：**新来的优先级不弱于当前的，就抢占；更弱，就丢弃**。被抢占的效果不会自行恢复。

## 常驻效果（hold）

缺省情况下，效果最长 30 秒后自动熄灭，防止网页崩溃后灯一直亮。hold 放开的就是这个 30 秒限制：

```json
{"c":"cue","id":"light.main","p":{"i":0.9,"ramp":800,"hold":true}}
```

- 回查状态时 ttl 报 -1，表示"没有时限"
- 被更高优先级抢占、被 reset、被看门狗清掉、断连 —— 四种情况都会释放它
- hold **不绕过看门狗**：15 秒没有有效帧，照样全部清空

> [!NOTE]
> 如果 hold 连看门狗都绕开，"玩家关掉浏览器，房间里的灯亮一整夜"这个事故就会重新发生。hold 放开的只是 TTL 上限。
