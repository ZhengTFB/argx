## 2. 核心原则

这一节是整个阶段的地基。**两条原则管两件事，不要混。**

### 2.1 界面长什么样 → 原型说了算

`design/` 目录是界面视觉的唯一权威，`design/prototype/*.html` 是其中的最终答案。

所有关于"这个按钮多高""这块留白多大""这个动效多快"的问题，
**答案都在原型里，不在你的判断里，也不在我的旧要求里。**

具体地：

- 颜色：从 `design/04-配色方案.md` 取，或直接从原型 CSS 里取变量值
- 间距、圆角、字号、阴影：全部走 `design/03-design-tokens.md` 的 token，**不写魔法值**
- 组件形态与状态：走 `design/05-组件清单.md`
- 动效时长与曲线：走 `design/06-动效清单.md`
- 页面分区：走 `design/02-页面线框.md`

文档与原型冲突时，**原型为准**。文档是解释，原型是事实。

### 2.2 界面上有哪些功能 → 底层代码说了算

**界面该实现什么功能，不看旧界面，看底层代码真实具备什么能力。**

"底层代码"指这些，按这个顺序读：

| 来源 | 能读到什么 |
|---|---|
| `protocol/PROTOCOL.md` | 协议全部命令与字段：`hello` / `cue` / `query` / `cfg` / `ping` / `reset` / `batch` / `hold`、能力声明 `caps`、反向通道 `input`、`err` 错误码、优先级、TTL、看门狗 |
| `firmware/argx_mvp/` | 设备端实际实现到什么程度、四种能力各自的参数含义、引脚 |
| `device/virtual_device.js` | 虚拟设备暴露的 `getState()` / `level()` 形状、故障注入开关有哪些 |
| `sdk/argx.js` + `sdk/AGENTS.md` | 事件词表、`fire()` 的能力过滤、静默降级行为 |
| `console/src/core/session.ts` | 会话层已经处理了什么（心跳、重连、ACK 匹配、抢占、TTL、幂等、看门狗） |
| `console/src/transports/` | 传输层契约 `connect` / `send` / `onMessage` / `close` |
| `console/src/works.ts` | 作品数据形状、`needs` / `optional` 字段 |

**做法：先把这些读完，列一张"底层实际具备的能力"单子**（第 2.3 节给了模板）。
界面上每一项都要能在这张单子上找到出处——**找得到才做，找不到先问我。**

### 2.3 「能力单子」长什么样（开工第一步就产出这张）

读完之后，你应该能填出这样一张表。**这张表不进交付物，但必须先在心里有，再动手。**

| 能力 | 底层出处 | 界面上该体现在哪 |
|---|---|---|
| 连上后设备自报能力 | `ready` 帧含 `caps` | 设备页能力列表；引导页据能力判断"你这台能玩什么" |
| 四路输出的强度/时长/渐变 | `cue` 的 `i` / `dur` / `ramp` | 模拟器四路控件；灯光/声音/振动有强度、继电器只有开关 |
| 一帧同时触发多个能力 | `batch`（上限 8 条 / 512 字节） | 调试页或测试台：多选目标时自动走 `batch`，展示逐条结果 |
| 长驻效果 | `hold`（`ttl` 报 `-1`） | 测试台的"常驻"开关；状态栏显示"常驻"而非倒计时 |
| 状态回查 | `query` → `state` | 右侧常驻状态栏、自检、模拟器可视化的**唯一数据源** |
| 双向：物理输入 | `input` 帧（`press` / `release` / `hold` / `change`） | 需要一处能手动注入 input 并看到上报的地方 |
| 心跳与掉线 | `ping` / `pong`，3s / 10s | 设备页心跳折线图（原型里已画） |
| 看门狗 | 15s 无有效帧 → idle | 不需要界面，但状态栏要能反映"输出被清空" |
| 故障注入 | `virtual_device.js` 的开关 | 模拟器内的故障面板 |
| 错误上报 | `err` 帧 | 调试页错误区 / 时间线里的错误行 |

> 把协议里**目前还没实现的**（`PROGRESS.md` 末尾列的十条协议缺陷，
> 例如 `state` 不回 `seq`、没有显式 `release`）**做成界面**就是发明需求。
> 那些不做，除非我另外说。

从 `design/03-design-tokens.md` 与两份原型里，把完整的变量集提取出来，
落成控制台实际使用的形式（Tailwind 配置 + 一份 CSS 变量）：

- **间距** 12 档
- **圆角** 7 档
- **阴影** 7 档
- **字号** 13 档
- **颜色**：按 `design/04-配色方案.md`，含语义色（成功 / 警告 / 错误 / 信息）

要求：

1. **禁止在组件里写魔法值。** 所有间距、圆角、色值都从 token 取
2. **禁止绕过 token 直接写 hex。** 例外只有一处：`design/04-配色方案.md` 里明确写了
   "此值不进 token"的（如果有，会在那里注明）
3. 原型里出现但 token 文档里没列的，**回头补进 token 文档**，不要就地写死
4. 首页与控制台**共享同一套 token 结构**，只有主题值不同（首页深色 / 控制台浅色）。
   不要把两套 token 各写一份

### 3.1 配色总则（照抄，不要漏）

`design/04-配色方案.md` 的六条总则全部有效。特别提醒第 6 条，这条是上一轮返工才加的：

## 4. 第二步：新建 `landing/`

官网首页，对应 `design/prototype/index.html`。

### 4.1 位置

新建 `landing/` 目录，与控制台并列：

```
argx/
├── landing/            # 官网首页（本阶段新建）
├── console/            # 控制台（本阶段重做）
├── design/             # 界面真源
├── protocol/  firmware/  device/  tests/  sdk/  demo/
└── docs/
```

### 4.2 技术选型

首页是纯静态单页，**不要为它引入 React**。用原生 HTML + CSS + 少量 JS，
或者与 `console/` 共用构建流程都行——**你自己判断，但要写进决策记录**。

判断依据：这份页面没有数据、没有路由、没有状态，
引入框架只会让它变重。但如果你发现共用 `console/` 的 Vite 配置更省事，也可以。

### 4.3 必须实现的内容

严格按 `design/prototype/index.html` 与 `design/02-页面线框.md` 第 1 节：

1. **开场动画**：三个词「更沉浸」「更恐怖」「更方便」，**全部在页面正中央原位替换**，
   不是错落堆叠。只在首次访问时播放，可跳过（ESC 或点击），用 `sessionStorage` 记忆
2. **动画期间，文字以外的元素不显示**
3. **定位句** + 产品界面展示
4. **两个大按钮**：一个给创作者、一个给开发者
5. **页底 GitHub 按钮**
6. **背景四层**：单点中性柔光 / 四角暗角 / 88px 网格 / 4.5% 噪点

### 4.4 两条必须做对的细节

**（1）首帧同步揭屏。** 原型 v2.1 修过一个真 bug：
非首次进入时所有元素不显示。根因是"判定要不要播动画"与"揭屏"被拆到了两个异步阶段。

正确做法是**判定与揭屏在首帧内同步执行**：

- 用 `visibility` 而不是 `opacity` 做可见性开关
- 不播放动画的分支里，**必须同步调一次揭屏函数**，不能只依赖后面的 `requestAnimationFrame`
- 末尾留一个保底函数，任何情况下都要让内容可见

这条**不要重新发明**，`design/prototype/index.html` 里已经是修好的版本，照着做。

**（2）`prefers-reduced-motion` 双重判断。** CSS 全局兜底 + JS `matchMedia` 各判一次。
只做 CSS 的话，JS 那侧仍会把开场动画跑一遍。

**ARG 库是作品目录，不是作品运行环境。** 里面的条目分两类，界面必须一眼分得清：

| 类别 | 去向 | 界面表现 |
|---|---|---|
| 自家 demo | 站内播放页 `#play:<workId>`，作品真的在跑，右侧状态栏跟着动 | 「试玩」+ 播放图标，主色底 |
| 第三方项目 | **新标签打开作者自己部署的网址** | 「访问作品站」+ ↗ 外链箭头 |
| 还没上线 | 只展示，点不动 | 「未上线」，按钮禁用 |

- 两类**都要**显示硬件备注（必需 vs「有了更好」）——那是 ARG 库的核心价值
- `works.ts` 的 `link` 字段表达这三种形态：内部 hash（`#play:<id>`）/ 外部网址 / 留空
- 数据**手工维护在 `works.ts` 里**，不做提交/注册界面

> **控制台不是作品托管平台。** 第三方作品永远跑在作者自己的站上，
> 这里只存一个网址。所以没有、也不该有「提交作品」「注册作品」这类界面。

### 5.4 文档页与调试页：你来填

这两页在原型里**只画了 UI 骨架**（三栏结构、树形导航、占位文字），内容没设计。

**由你填实。** 理由：只有你读过协议、固件、SDK 的全部细节，你知道该写什么。

**文档页**——写文档是这个阶段的重要任务，不是凑数：

- 结构照原型：左树形导航 / 中内容 / 右上"本页目录"（带进度条）
- 内容要**真的有用**，覆盖面至少包括：
  - 快速开始（三步走：装什么、连什么、怎么验证）
  - 连接方法（驱动、数据线、端口选择、两个 USB 口的区别）
  - 指令表（协议全部命令 + 参数 + 示例）
  - 能力与参数说明（四种能力各自的参数含义、连续量 vs 开关量）
  - 错误码（`err` 帧的全部错误类型 + 怎么排查）
  - 故障排查（连接不上、灯不亮、装上没反应）
  - 给创作者的部分：怎么在作品里埋点（可以从 `sdk/AGENTS.md` 取）
- 内容从 `protocol/PROTOCOL.md`、`firmware/WIRING.md`、`sdk/` 里**提取重写**，
  面向不懂硬件的人。`firmware/WIRING.md` 讲装置侧接线，这里讲电脑侧连接与排查，**不重复**

**调试页**——按底层真实具备的调试能力设计：

- 原型已画：三栏（或其他你判断更合适的分区）
- 必须包含（这些都对应底层真实能力）：
  - **收发时间线**：实时滚动展示全部收发事件，支持只看帧 / 只看错误、自动滚动、清空。
    这是旧"时间线"栏目的能力，**在这里落地**
  - **手动发 cue**：选能力 id、填参数、发送，看到设备回执
  - **故障注入**：把 `virtual_device.js` 的注入开关做成 UI（不发 `ready`、
    延迟 3 秒、随机丢包、垃圾 JSON、中途断连）
  - **input 注入**：手动注入反向通道帧，验证上行链路
- 怎么分区、要不要拆子页，**你自己判断**，但要把判断写进决策记录

### 5.5 模拟器怎么建

原型里已经画好了（`design/prototype/console.html` 的模拟器页 + `design/02-页面线框.md`）：

- 四路各有可视化。**连续量（灯光/声音/振动）要有过程感，开关量（继电器）只有两态**
- 触发方式：手动发 cue + 剧情预设按钮
- 故障注入面板挂在模拟器内

**技术约束（沿用阶段二已验证的做法，不要改）：**

- 直接复用 `device/virtual_device.js`，**不复制不重写**
- 可视化用 `requestAnimationFrame` 读 `device.getState()`，**不进全局 store**
- 按签名比较（`ttl` 按 50ms 粒度）避免全帧重渲染
- 模拟器进来**自动连虚拟装置**，不该要求用户先做一次"连接"动作

### 5.6 hash 空间重定

新界面只有一套，hash 按新栏目重写：

```
#onboarding   #library     #device
#simulator    #docs        #debug
#play:<workId>            # 自家作品的站内播放页（不算一级栏目）
```

`#play:<workId>` **不是第七个栏目**：它属于 ARG 库，进去之后顶部「ARG 库」那一格仍然高亮，
侧栏与顶栏都不新增项。加它的原因见 5.3 节——作品目录里有两种条目，
自家 demo 需要在控制台里真的跑起来，第三方项目则是外链。

**旧 hash（`#overview` `#home` `#works` `#timeline` `#creator` `#help` 等）的处理：**

- `#device` `#library` `#simulator` `#docs` 这四个**语义没变，可以直接复用**
- 其余旧 hash **重定向到最接近的新栏目**，不要留死链
- **重定向必须同时改写地址栏**（`history.replaceState`）。只做内部跳转的话，
  地址栏里会躺着一个已经不存在的页面名，而且「不留死链」这件事没法被断言
- 具体映射见决策记录

**白名单文件**：`console/scripts/` 下的冒烟脚本会打 hash，一并改。

### 5.7 界面冒烟重写

旧的 `scripts/smoke.mjs`（专业版 26 项）与 `scripts/smoke-basic.mjs`（小白版 34 项）
**按新界面重写**。

要求：

## 7. 动效与适配准则

### 7.1 动效（电脑端）

**全部照 `design/06-动效清单.md` 执行。** 这里只列总则，避免你只看总则就动手：

- **hover 为主**，不做点击按压缩放
- **所有可交互元素必须有键盘 focus 态**，焦点可见
- **只动 `transform` / `opacity` / `filter` / 颜色 / `box-shadow` / `clip-path`**
  ——不动 `width` / `height` / `top` / `left` / `margin`
- 时长分档：`80–120ms` 微反馈 / `120–180ms` 状态切换 /
  `200–350ms` 面板进出 / `300–400ms` 页面切换 / `400–600ms` 强调
- **全部支持 `prefers-reduced-motion`**（CSS + JS 双判）
- **连续量与开关量的切换动效必须不同**：
  连续量渐变（`260ms`），开关量硬切（`0ms`）。这是设计的一部分，不是偷懒

### 7.2 适配

- **只做电脑端。** Web Serial 的场景约束决定了这是桌面工具
- 但不要写死像素宽度而导致窗口变窄就崩。最小可用宽度按 `design/02-页面线框.md` 的约定
- 手机端不要求可用，但**不要出现横向滚动条**

## 8. 风格红线（沿用 `design/` 的结论）

避免"AI 味"这件事已经返工过一轮了，这些结论直接照做：

| ❌ 不要 | ✅ 要 |
|---|---|
| 卡片套卡片、每层都加阴影 | 一层容器，阴影只用在真正浮起的元素上 |
| 所有卡片一样大 | 按信息重要性区分尺寸 |
| 霓虹、高饱和、多色相彩色渐变 | 中性冷调 + 同色相明度渐变 |
| 每个标题配一句解释 | 标题自己说清楚，不配解释句 |
| 圆角阴影间距各处不一 | 全部走 token，7 档圆角 / 12 档间距 |
| 装饰性的脉冲点、胶囊标签 | 删掉。信息能自己表达就不加装饰 |
| 粒子、光带等"廉价科技感" | 中性柔光 + 网格 + 噪点，纯静态 |
