## 1. 本阶段目标

产出一个**能在我电脑上跑起来、能直接看到界面**的控制台网站。

控制台是整套系统的中枢：连接管理、设备测试、能力查看、作品浏览、文档查阅，并内置模拟器让没有硬件的人也能看到整套东西怎么运作。

交付后应达到：我执行一条启动命令，打开浏览器，能看到完整控制台，点进模拟器能触发四种能力并看到可视化反馈。

## 2. 技术栈与硬约束

Vite + React + TypeScript + Tailwind CSS。

选它的理由：组件化管理设备列表、能力面板、实时日志流最顺手，构建产物是纯静态文件可直接部署。

**约束**：

- 构建产物为纯静态文件，无服务端依赖，可直接上传到任意静态服务器
- 代码里不写死域名或绝对路径，全部用相对路径
- 提供一条本地启动命令，我需要在本机 `localhost` 打开查看

**与 SDK 的区别**：控制台可以用构建工具和框架。阶段三的 SDK 必须零依赖纯原生 JS，能整段复制进第三方单文件 HTML。两者是不同产物，不要用控制台的方式去写 SDK。

## 3. localhost 约束

Web Serial 要求安全上下文（HTTPS 或 localhost）。本机调试用 `localhost` 即可免除证书。

若用局域网 IP（如 `192.168.1.5:5173`）访问，`navigator.serial` 会直接不存在，串口功能消失。模拟器不依赖串口，局域网 IP 下仍可正常演示——想给别人看效果但不想让他装硬件时，用局域网 IP 让他看模拟器即可。

串口相关测试必须在本机 `localhost` 上做。

### 4.1 总览

一屏看完当前状态：连着什么装置、用的哪种传输、在线还是离线、刚才触发了什么。作为打开控制台的第一眼。

### 4.2 设备

- 已连接装置列表与在线状态
- **能力可视化**：直接渲染 `caps` 内容，展示这个装置能做什么
- **手动测试台**：选一个能力 id，填参数，手动发送 cue——用来测试"灯能不能亮"
- **连接测试**：心跳状态、延迟、连续发 N 次 ping 看稳定性
- 掉线时明确通知，并回到未连接态

检测与调试能力集中在这里，不放进 SDK——这是总纲定的归属原则。

### 4.3 ARG 库

- 支持本项目的作品列表
- 每个作品附一张**硬件需求备注**：写明需要哪些装置（如"需要 light.main 与 sound.beeper"）
- 备注为**人工标注**，不自动识别代码
- 没有对应硬件的玩家，给出"可以去买"的引导

**扩展位要求**：作品列表用数据驱动（独立的配置文件或数组），我以后要加新作品时，只加一条数据即可，不改任何组件代码。

### 4.4 文档

- ESP32 与电脑的连接方法（驱动、数据线、端口选择）
- 各硬件模块对应的引脚与端口号，整理成表
- 常见连接故障排查

要求具体、可照做。面向不懂硬件的人。（与阶段一 `firmware/WIRING.md` 的分工：那边讲装置侧引脚接线，这边讲电脑侧连接与排查，不重复。）

### 4.5 时间线

记录所有收发事件，实时滚动展示。调试时最有用的东西，也方便回溯某一局触发了什么。

## 5. 模拟器（本阶段重点）

模拟器让没有 ESP32 的人点进去就知道这套东西怎么运作。

### 5.1 复用阶段一成果

模拟器直接复用阶段一的 `device/virtual_device.js`，不重新实现协议逻辑。阶段一已暴露状态查询接口，模拟器读取它并渲染。

### 5.2 虚拟装置可视化

绘制一个虚拟装置，四种能力都要有直观的视觉反馈：

| 能力 | 可视化方向 |
|---|---|
| `light.main` | 灯的明暗变化，支持渐变过程 |
| `sound.beeper` | 声波/涟漪动画 |
| `motion.vibrate` | 抖动动画 |
| `env.relay` | 开关状态指示 |

目标是让"触发 → 协议 → 设备 → 视觉效果"整条链肉眼可见。

### 5.3 触发方式

- 手动触发：选能力 id、填参数、发送
- 模拟剧情触发：提供几个预设按钮，模拟"解谜成功""进入新场景"这类剧情节点

### 5.4 故障注入面板

把阶段一虚拟设备内置的注入开关做成 UI：

- 不发 `ready`
- 延迟 3 秒应答
- 随机丢包
- 发送垃圾 JSON
- 中途断连

用途是验证控制台在各种异常下的表现。

## 6. 传输层

控制台实现两个 Transport，接口统一：

- **Mock** — 连接虚拟设备，本阶段默认与主力
- **Serial** — Web Serial 连接真实 ESP32，本阶段实现但仅做连通性验证

Transport 接口与阶段一保持一致（`connect` / `send` / `onMessage` / `close`）。未来加 WebSocket 等其他传输时，只加一个实现。

界面上要能看出当前用的是哪种传输。
